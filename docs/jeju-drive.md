# 제주 해안–한라산 주행 Scene · 확장판

Unity **2022.3.16f1**에서 `Assets/_Parkside/Scenes/JejuCoastalDrive.unity`를 열고 Play한다. 메뉴에서도 `PARKSIDE → Jeju → Open coastal drive`로 연다. 기존 주차장과 분리한 PC 주행 시안이다.

## 경로와 지형

- 예래 해안 → 중문 → 1100도로 → 1100고지 부근, 현재 주 경로 약 **23.1km**. 교통 확장판에서 산길도 방향 그래프로 다시 연결했다. 실제 지리 좌표를 지역 평면 좌표로 옮겼으며 **1 Unity unit = 1m**다.
- 대포·중문 해안, 중문 시가지 순환, 예래 마을 연결도로와 교차로 진입로를 추가했다. 직접 운전할 때 교차로에서 연결도로로 갈 수 있다. 풍경 주행은 주 경로를 따른다.
- 막다른 길로 들어갔다가 즉시 반대로 회전하는 동선은 풍경 주행에서 제외했다. DEM의 급격한 요철은 연결 도로 전체에서 함께 완화해 주 경로의 최대 경사를 약 16%로 제한했다. 높이는 주행용 근사이며 도로 측량값은 아니다.
- OpenStreetMap의 공개 도로를 연결했다. 확장 경로 검색은 일방통행·사유지 태그를 반영했다. 약 5m 간격으로 샘플링하고 교차로의 날카로운 폴리라인 모서리를 수 m 범위에서 완화했다. 실제 도로 위치·큰 굴곡을 유지하는 주행용 근사다.
- 지형은 Mapzen Terrain Tiles의 실제 DEM이다. 도로 고도 약 5–1,097m, 한라산 정상 부근 DEM 약 1,926m다. DEM은 측량급 자료가 아니며 도로 고도는 짧은 구간의 급격한 요철을 완화했다.
- 한라산과 서쪽 해안을 포함한 원경 지형은 약 **20.5×19km** 범위다. 근거리 식생은 도로 주변, 먼 수관은 수백 m 깊이로 구성했다. 도로가 다시 만나는 구간도 동일한 고도장을 사용한다.
- 고지대가 종점인 편도 코스다. 직접 후진·회차하거나 구간 이동으로 돌아갈 수 있다. 풍경 주행은 종점 근처에서 정지한다.

도로 밖으로 멀리 벗어나지 않도록 노견에서 속도를 줄이고 도로 경계 안으로 제한한다. 연결도로에서도 운전·도로 복귀를 사용할 수 있다. 차량은 경사에 맞춰 움직이는 자전거 모델 기반의 주행 프리뷰다. 주변 NPC 교통을 포함하며, 정밀 타이어·서스펜션 물리와 Pleos 입력은 아직 연결하지 않았다.

## 차선과 신호

실제 OSM 교차로 노드에 게임용 신호를 구성했다. 기존 해안·산길의 7개 교차로와 신시가지에서 신호가 태그된 7개 노드를 사용한다. 분리차로의 가까운 노드 쌍은 같은 주기로 제어한다. 등주 배치와 신호 주기는 시뮬레이션 값이다.

- 중앙선·노측선, 넓은 도로의 차로 구분 점선, 정지선·횡단보도·진행 방향 표시.
- 주도로 녹색 30초 → 황색 4초 → 전 방향 적색 3초 → 교차도로 녹색 20초 → 황색 4초 → 전 방향 적색 3초. 교차로마다 시작 위상이 다르다.
- 풍경 주행은 적색·황색 신호에 감속·정지하고 녹색에 다시 출발한다.
- 직접 운전에서는 적색 정지선 통과를 감지해 화면에 안내한다. 정밀 교통법규 채점 체계는 아니다.

## 서귀포 신시가지 · 2026-11-10

- 강정 해안 순환도로에서 월드컵로, 서호남로, 신중로와 공동주택 주변 길을 이어 직접 운전할 수 있다. NPC의 실제 도로 방향 그래프는 약 55.8km에서 64.2km로 넓어졌다. 화면 지도에서 주요 신시가지 길을 황금색으로 표시한다.
- 법환·서호·강정 생활권의 건물 윤곽 357개를 불러오고, 주행면과 겹치는 윤곽은 배치에서 제외한다. 상가에는 유리 전면과 한글 간판, 공동주택에는 발코니, 큰 길에는 보도와 가로등을 배치했다. 도로에 면한 상가 앞에는 보도에 이어지는 포장 공간을 만들었다. 높이 태그가 없는 건물의 층수와 외관은 용도에 맞춰 추정했다.
- 제주월드컵경기장의 초승달형 막 지붕과 서귀포시청 제2청사를 도로에서 보이는 지표로 만들었다. 실제 외곽에 씬 전용 모델을 배치했다. [경기장 구조 설계사](https://www.thorntontomasetti.com/project/jeju-world-cup-stadium) · [서귀포시 제2청사 주소](https://parking.seogwipo.go.kr/period/list)
- `JejuBuildingAuthoring`은 건물 외곽·외장과 건물 블록을, `JejuMeshGeometry`는 공용 메시 생성을 담당한다. 주행과 카메라·HUD를 나눴으며, 플레이어 풍경 주행의 주변 차량 겹침 판정을 공용 차체 형상으로 묶었다.
- 시가지 미리보기는 `build/jeju-drive/seogwipo/`에서 확인한다.
- 저장한 Scene의 아스팔트 충돌 검사 10,791점, 해안 거점 도로 간섭 0건. 신시가지 건물 355개를 배치했다. 폭이 맞지 않는 건물 외곽 2개는 제외했다.
- 실제 Play Mode에서 직접 주행 연결 경로 49개, NPC 차로·회전의 아스팔트 검사 56,364점, 10개 출발 위치의 차량 이동, 신호 정지·재출발, 23.1km 주 경로 풍경 주행을 확인했다. 시가지 출발점에서 NPC 24대가 목적지 20곳으로 나뉘었다.
- 로그와 결과는 `build/jeju-drive/unity-seogwipo-final.log`, `unity-seogwipo-traffic-lanes.log`, `scene-report.txt`, `traffic-play-report.txt`, `play-report.txt`에 있다.

## 데이터와 생성 도구

- `tools/prepare-jeju-drive.py`: 공개 도로와 DEM 다운로드·캐시, 연결 경로 계산, 고도 샘플, 지도와 경로 JSON 작성. Python + numpy + Pillow 필요.
- `tools/prepare-jeju-expansion.py`: 현재 확장판의 데이터 생성 도구. Python + numpy + Pillow + SciPy 필요. `OriginalCoastalRoute.json`을 기준으로 확장하므로 반복 실행해도 경로가 중복 확장되지 않는다. 현재 확장판을 다시 만들 때는 이 도구를 사용한다.
- 원본 다운로드 캐시: `build/jeju-drive/source/`. 실행 중에는 네트워크가 필요 없다.
- `Assets/_Parkside/JejuDrive/Data/SourceRoads.geojson`: 사용한 OSM 도로와 태그. ODbL 1.0으로 제공하는 파생 지리 데이터.
- `ContextGeography.geojson`, `ContextSources.json`: 확장 지역의 공개 도로·건물 윤곽과 원본 다운로드 해시. 지리 데이터는 ODbL 1.0이다.
- `JejuRoadData.json`, `TerrainHeights.bytes`: Scene 작성에 사용한 로컬 경로·고도.
- `JejuDriveBuilder`: 명시적 초기 생성 도구. 메뉴의 초기 생성 명령은 기존 Scene을 덮어쓰지 않으며, 일반 빌드나 Editor 시작 시 자동 생성하지 않는다. 개발용 배치 진입점 `RefineDraftAndVerify`는 이 생성기의 Scene을 재작성하고 생성 메시·재질을 GUID 유지 상태로 갱신하므로, Scene을 직접 편집한 뒤에는 실행하지 않는다.
- `JejuDriveVerification`: 명시적으로 실행한 검증에서만 저장·재열기, 도로 충돌체 연속성, 실제 Play Mode에서 수동 가속·제동·후진·복귀·시점과 전체 풍경 주행을 확인한다.
- `build/jeju-drive/`: 컴파일 로그·검증 보고서·구간별 미리보기. 실제 결과는 해당 로그를 따른다.

출처와 라이선스는 [JejuDrive/CREDITS.md](../unity/InputProbe/Assets/_Parkside/JejuDrive/CREDITS.md)에 기록했다.

## 주변 교통과 동쪽 해안 확장

- 대포에서 월평·강정을 지나 기존 마을 도로로 연결되는 약 15.7km 순환 경로를 추가했다. 기존 경로와 공유하는 구간이 있으므로 이 길이를 모두 신규 도로 길이로 합산하지 않는다. `5` 키로 월평·강정 구간에 이동한다.
- `JejuTrafficNetwork.json`은 실제 OSM 노드와 way ID로 구성한 방향 그래프다. 가까이 지나가는 도로를 거리만으로 연결하지 않는다. 일방통행, 회전교차로 진행 방향, 자동차 통행 제한, via-node 회전 금지·지정 회전 관계를 반영한다. 각 간선에는 원본 노드, 차로 수·방향별 차로·제한속도·차로별 회전 태그를 보관한다. 현재 NPC는 다차로 도로의 한 개 진행 차로를 사용하며 차로 변경은 하지 않는다.
- 최대 24대의 풀을 사용한다. 플레이어 약 70–420m 주변에서 안전 간격을 두고 생성하며, 카메라 앞 가까운 곳은 피한다. 각자 무작위 목적지를 정해 도로망을 탐색하고, 약 650m 밖이나 목적지에 도달하면 풀로 반환한다. 고지대의 긴 끝 구간에서도 양방향 차량이 이동한다.
- 기존 투싼·i30·아제라의 경량 모델을 재사용한다. 앞차 및 플레이어 감지, 차간거리, 신호 정지·재출발, 교차로 진입 순서, 합류 시 받는 차로의 간격, 회전 궤적과 방향지시등·브레이크등을 처리한다. 회전교차로는 방향 그래프와 합류 간격으로 운행한다.
- 실제 반대편 일방통행 도로와 회전교차로를 함께 생성했다. 일방통행 도로는 흰색 차로 구분선을 쓰고 양방향 도로는 중앙선을 사용한다. 회전교차로 진입 차량은 이미 회전 중인 차량을 먼저 보낸다.
- 신호 교차로의 도로 팔은 실제 도로 접선으로 구성한다. 교차로의 연결 형태는 OSM에서 가져오지만, 횡단보도·등주 위치와 신호 주기는 현장 조사값이 아닌 시뮬레이션 배치다. 실제 도로의 모든 표지·차로 규제를 복원한 디지털 트윈은 아니다.
- `tools/prepare-jeju-traffic.py`는 도로망을 생성하고, `tools/check-jeju-traffic-data.py`는 원본 일방통행 방향·회전 관계·주행면 정렬을 검사한다. `JejuTrafficVerification`은 실제 Play Mode에서 생성·서로 다른 목적지·교차로 회전·대기열·플레이어 장애물·풀 반환을 검사한다. 실행 결과는 `build/jeju-drive/traffic-*.json`, `traffic-play-report.txt`에 기록한다.

## 서귀포 로드뷰 반영 · 2026-11-10

Unity에서 제주 씬을 열고 Play한 뒤 `0`을 눌러 대청로를 확인한다. 2026년 3월 촬영분의 간판 띠, 외벽 색조, 창호 간격, 상가 차양, 보도, 중앙선과 차로 구분선을 관찰했다. 창을 벽 안으로 넣고 창틀·발코니·외장 줄눈을 별도 형태로 만들었다. 제2청사 쪽은 청록색 유리와 어두운 수직 프레임을 적용했다.

- [대청로 상가와 주거동](https://map.kakao.com/link/roadview/33.25253,126.50341) · [대청로 동쪽 교차로](https://map.kakao.com/link/roadview/33.25248,126.50468)
- [신중로 제2청사](https://map.kakao.com/link/roadview/33.25506,126.50998)
- [월드컵로 경기장 입구](https://map.kakao.com/link/roadview/33.2466,126.50705) · [경기장 상업시설 주차장](https://map.kakao.com/link/roadview/33.24858,126.5080)

대청로와 경기장 앞 월드컵로는 관찰한 다차로 구간에 맞춰 아스팔트와 차선 폭을 조정했다. 차로 폭, 창 개수와 층고는 관찰 및 지도 정보에서 추정한 값이다. OSM에 빠진 대청로 주변 건물 윤곽은 [Overture 2026-10-21.0](https://docs.overturemaps.org/blog/2026/10/21/release-notes/)에서 보충했다. 로드뷰 사진은 시각 참고에 사용했고 씬의 재질과 형상은 직접 제작했다.

`tools/prepare-seogwipo-street-reference.py`가 기존 OSM 도로망, 공개 건물 윤곽, 주차장 폴리곤을 `SeogwipoStreetReference.json`으로 정리한다. Unity 배치 진입점 `RefreshUrbanDistrictAndVerify`가 시가지와 도로 상세를 저장하고 Play Mode 검사를 시작한다. 캡처와 검증 결과는 `build/jeju-drive/seogwipo/`에서 확인한다.


대청로 기준 구간은 주변 도로 높이와 로드뷰에서 관찰한 완만한 형태를 바탕으로 경사를 보정했다. 기존 원본 고도와 변경본 메시를 각각 보관하고, 동일한 보정치를 도로 표면과 차량 경로에 사용한다.

최종 저장본은 지형을 함께 둔 새 차로 검사 1,341점, 기존 도로 검사 10,791점, NPC 생성과 49개 연결도로의 수동 주행, 23.1km 자동 주행을 통과했다. `build/jeju-drive/unity-street-grade-clearance.log`와 `verification-complete.txt`에서 확인한다.

## 대청로 가로 시설과 상가 전면

기존 `ParklingLot.unity`에서 사용하던 상가 사진 질감, 창호 깊이, 아스팔트 보수 재질과 카메라 마감을 재사용했다. 대청로 주변 상가의 한글 가로 간판과 양면 돌출 간판은 별도 메시와 글자로 제작했다. 상호는 연출용이다.

대청로·제2청사·월드컵경기장·버스터미널 안내판, 정류장, 콘크리트 전신주와 처진 전선, 주철 맨홀과 빗물받이, 줄눈이 있는 연석을 배치했다. 안내판은 실제 지명에 맞춰 현장 분위기를 재현한 모델이다. 도로 경로는 이전에 검증한 OSM 및 로드뷰 참고 형상을 유지했다.

검증 로그는 `build/jeju-drive/unity-street-finish-final.log`, 가로 시설 검사와 도로 높이 캡처는 `build/jeju-drive/seogwipo/`에 있다.

외벽과 간판만 다시 저장할 때는 `Parkside.Jeju.Editor.JejuDriveBuilder.RefreshSeogwipoFacadeFinishBatch`를 사용한다. 기존 도로와 차량 설정을 읽어서 유지하고, 새 외벽이 저장된 씬을 다시 열어 재질과 도로 표면을 검사한다. 확대 캡처는 `seogwipo-shopfront-finish.png`다.

해안·마을 연결도로를 포함해 기존 건물 전체의 외벽을 갱신할 때는 `Parkside.Jeju.Editor.JejuDriveBuilder.RefreshJejuFacadeFinishBatch`를 사용한다. 예래·중문과 서귀포 시가지의 외벽에 벽돌, 회벽, 회색 석재, 현무암을 나누어 쓰고, 주거 출입구와 상가 전면을 구분한다. 상점 정보가 있는 건물은 그 이름을 우선 사용하며, 나머지 상호는 장면에 맞춰 제작했다. 해안·마을 주행 시점 캡처는 `build/jeju-drive/seogwipo/jeju-corridor-*.png`다.
